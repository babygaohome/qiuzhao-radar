# 自动招聘发现（第一版）

后台 api 的现有每10分钟维护触发器，在北京时间 07:00–24:00 的每小时 :20、:40 执行一小步。搜索与逐条原文提取分开运行，租约阻止重叠执行。无需前端升级。

默认读取 job.hust.edu.cn、career.csu.edu.cn 的公开公告。搜索发现与中南大学公开公告列表轮换，列表读取不消耗搜索API额度，正文处理仍受AI总额度限制。轮换会计、法务、交付、行政、运营、传媒、机械、物流、教育、计算机十类关键词。搜索最多10次/日，公开列表读取最多10次/日，仍受全站45次、后台25次搜索总额度及AI总额度约束。不是平台全站抓取。

新增环境变量（均可不填）：
- DISCOVERY_ENABLED=off：停用发现；默认启用。
- DISCOVERY_ALLOWED_HOSTS：额外经过审核的公开来源精确主机名，英文逗号分隔。添加前检查站点条款及采集限制，不能用它绕过登录或访问控制。
- RECRUITMENT_COHORT：默认2027。

线索和运行摘要保存在已禁止客户端读写的 meta 集合：discovery、discoveryLastError、lead_*、discoveryLease。线索30天到期，分批清理。搜索摘要不作为原文证据。

公司名和岗位引用必须出现在读取的正文中，必须明确目标届次及校招属性；明确截止未过或有45天内的明确发布日期才能自动入库。未知/过期/无法读取进入 needs_review，不会对用户展示为已核实。学历、城市、截止仅在该岗位引用中出现才保存为岗位字段；页面其他位置的日期不冒充岗位要求。新公司仍为 single；高校转载不冒充企业官网。

公司ID复用现有采集的公司名规范化规则；已有公司只补 discoveryEvidence，保留当前岗位、核实及投递数据。只处理公共公告，不读取任何用户资料。BOSS/智联等非白名单结果仅记外部线索，不请求页面。

目前提取每篇最多2个岗位（校验上限10），不能保证覆盖所有岗位；图片公告、未注明日期、登录页面或跳转页面不会自动发布。已有公司岗位列表不被此模块替换。后续可按数据验证增加来源和岗位级展示。

验证：node security/discovery.test.cjs；node security/isolation.test.cjs。

## 全国企业公众号发现

新增31个省级地区轮换的公开检索，每四个发现轮次中一个采用“届次＋地区＋岗位方向＋企业官方公众号”搜索；仍使用原每日搜索上限，不额外扩大额度。地区是搜索线索，并不代表企业总部或岗位所在地。要完成一轮全国检索需要多个运行日，不保证覆盖所有企业公众号。

微信文章首先标记 identity_review，不请求未确认主体的公众号页面，也不发布为企业。meta/discoveryAccountRegistry.accounts 可存经管理端核对的主体映射（biz、company、proofUrl、verified=true、verifiedAt），180天后要求重新确认；没有默认认证记录。认证是管理端确认企业官网与公众号主体对应关系，不能由AI自行填verified。带明确__biz且认证有效的文章才进入现有正文校验；短链接需要另行确认身份。企业名必须与认证主体一致，否则不入库。站点访问失败、有效日期未知、岗位无原文均不自动发布。

本轮完成检索轮换、主体拦截及身份确认后的旧线索自动重入队列，已通过本地测试并上传扩展；未验证全国检索效果，也尚未建立经核实的企业公众号目录。微信公众号全文的发布日期格式、图片岗位和访问限制尚需逐来源验证，不能把“代码支持”称为“已稳定自动收录公众号”。

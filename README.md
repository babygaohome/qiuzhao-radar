## v2.5.0：岗位证据与个人匹配

从AI结果卡点击“查看证据与JD匹配”，或在公司详情点击同名入口。页面先显示公司级参考，再提供岗位JD与个人材料分析。填写岗位JD原文/职位页链接，并粘贴已去除联系方式及证件号的简历文字，或选择本人材料；确认后发送至既有智谱服务。

结果分别列出匹配点、材料未体现的要求和未知项，带原文引用。五项要求没有可靠原句就显示“未确认”；公司级要求不能当作该岗位要求。用户粘贴的JD未被独立认证，分析不是录用概率或资格保证。只保留本人最近20条结果及必要引用，不保存完整JD/简历；再次推荐可使用最近7天的本人岗位证据。全量删除本人数据会清除结果，旧备份中的分析需要重新生成。

云函数接口：`getMatchContext({id,role?})` 返回本人材料标题、本人此前分析和公司级证据；`matchJob({id,role?,jd,resume?,materialIds?})` 校验公司访问权、只选择本人材料，每人每天最多15次，返回私有五项证据与三类分析。输入JD最多8000字符、合并个人材料最多10000字符，结果引用最多160字符。拒绝无微信身份访问；不新增公共写入权限或提高全站搜索预算。

## 要花钱吗

- 注册个人小程序：免费。
- 云开发：小程序**没有正式发布**时，免费环境一直免费（额度 20 万次调用、2 GB 存储，够用）。发布上线 15 天后要转付费（基础版 19.9 元/月）。官方活动截止到 2026 年 12 月 31 日，之后以官方公告为准。
- AI：按你选的服务商计费，和微信无关。不配置 AI 也能用，只是「AI 挑选」用不了。

建议只用**体验版**：自己和同学扫码使用，不用审核也不用发布。个人主体一般选不了「招聘」类目，数据也来自第三方汇总站，不适合公开发布。

## 第一次部署

### 1. 注册小程序，拿到 AppID

打开 <https://mp.weixin.qq.com> → 立即注册 → 小程序 → 主体类型选「个人」。注册后在「开发管理 → 开发设置」里能看到 **AppID**。

### 2. 用微信开发者工具打开项目

1. 下载安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 导入项目 → 目录选 `qiuzhao-mp` 文件夹 → AppID 填你的 → 后端服务选「微信云开发」。

### 3. 开通云开发

1. 工具栏点「云开发」→ 开通 → 创建环境（选免费环境）。
2. 在云开发控制台的「设置」里复制**环境 ID**，填到 `miniprogram/config.js` 的 `envId`。
3. 「数据库」里新建 4 个集合：`companies`、`apps`、`profiles`、`meta`。每个集合的「数据权限」都改成「自定义安全规则」，内容填：

   ```json
   { "read": false, "write": false }
   ```

   这样只有云函数能读写数据，别人没法直接读到你的投递记录。

### 4. 部署云函数

在开发者工具左侧文件树里右键 `cloudfunctions/api` →「上传并部署：云端安装依赖」。

然后到云开发控制台 → 云函数 → `api` → 版本与配置：

- **超时时间**改成 60 秒（AI 挑选需要）。
- **环境变量**填 AI 服务（不用 AI 可以先不填）：

| 变量 | 说明 |
|---|---|
| `AI_BASE_URL` | 接口地址，见下表 |
| `AI_API_KEY` | 你在服务商那里创建的密钥 |
| `AI_MODEL` | 主模型 |
| `AI_QUICK_MODEL` | 可选，第一步扩展关键词用的便宜模型，不填就用主模型 |
| `AI_JSON_MODE` | 可选，某个服务报错时填 `off` |

常见的兼容 OpenAI 格式的服务（模型名会更新，以服务商文档为准）：

| 服务 | AI_BASE_URL | AI_MODEL 示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`（快速：`qwen-turbo`） |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| Kimi | `https://api.moonshot.cn/v1` | 以 Kimi 开放平台文档为准 |

密钥只存在云函数的环境变量里，不会出现在小程序代码里。

### 5. 导入公司数据

```bash
cd tools
python3 -u collect.py          # 收集，第一次要读详情页里的官方链接，大约 2–3 小时；之后只读新增的
python3 sync_cloud.py          # 生成 out/cloud_import.json
```

然后二选一：

- **手动导入**：云开发控制台 → 数据库 → `companies` → 导入 → 选 `tools/out/cloud_import.json` → 冲突处理选 **Upsert**。
  手动导入不会删除已截止的公司，列表会自动隐藏它们。
- **自动同步**：设置环境变量后再运行 `sync_cloud.py`，会上传、导入并清理已下线的公司：

  ```bash
  export WX_APPID=你的AppID
  export WX_SECRET=你的AppSecret     # 小程序后台 → 开发管理 → 开发设置
  export WX_ENV=你的环境ID
  python3 sync_cloud.py
  ```

  第一次需要把这台电脑的公网 IP 加到小程序后台 →「开发管理 → 开发设置 → IP 白名单」，否则会提示 40164。

### 6. 在手机上用

- 开发者工具点「预览」扫码，或「上传」后到小程序后台 → 版本管理 → 设为**体验版**。
- 同学要用：小程序后台 → 成员管理 → 添加体验成员。每个人的投递进度和 AI 推荐各自独立。

## 自动更新（云端定时采集）

`cloudfunctions/crawler` 由定时触发器每 30 分钟运行一次（每小时第 7、37 分钟，全天），抓六个公开校招列表：秋招网、牛企直聘、offer多多、OfferStar、JOBUP、华中科技大学就业网。秋招网、offer多多、JOBUP、高校就业网每次都抓首页，同时轮换检查后续页：

- 新出现的公司直接加入，已有公司合并截止日期和来源；
- 轮换的后续页只用于发现未收录企业，不用部分页面里的岗位覆盖已有公司的完整列表；
- 牛企直聘按行业轮换，正常完成时约每 2 小时轮完 27 个行业首页，并逐次检查一个行业的第 2 页；
- OfferStar 和 JOBUP 只提取公开列表里的校招摘要；它们的外链不自动算企业官方入口，新收录的单一来源公司仍需核实；
- 高校就业网只收明确写出 2027 届校招的公告，保留高校公告页作出处；高校链接不冒充企业官网，单一来源仍显示待核实；
- 过期招聘不会新入库；后续页里没有明确截止日且超过 45 天未更新的公司也不会新入库；
- 每次顺便给 10 家新公司补官方链接；
- 运行记录在数据库 `meta/crawler` 里（各来源抓到多少、分页范围、各来源新增多少、用时）。

部署或修改后：右键 `cloudfunctions/crawler/config.json` →「上传触发器」，并在控制台把它的执行超时设为 60 秒。

## 日常更新数据（可选的完整刷新）

云端采集只看各站最新的几页。想补全更早发布、之前漏掉的公司，可以偶尔（比如每周）在电脑上跑一次完整收集，再用 Upsert 导入：

```bash
cd tools && python3 -u collect.py && python3 sync_cloud.py
```

## 使用说明

- **核实标记**：官方 = 找到了企业自己的招聘公告或投递页；多源 = 多个汇总站都收录了；单源 = 只有一个汇总站收录，先去官网核实；疑似中介 = 名称或岗位像猎头、人力外包。
- **投递链接**：个人小程序打不开外部网页，详情页的链接点一下会复制，粘贴到浏览器里打开。
- **AI 挑选**：云函数先按你的专业、岗位、城市给所有在招公司打分，挑出约 70 家候选，再让 AI 选出最适合的十几家，并写明理由和投递建议。AI 只看到公司名、行业、城市和在招岗位，看不到薪资和学历要求，投递前以官方公告为准。
- **不想看的公司**：详情页底部可以「不再显示这家」，只对你自己隐藏。

## 2026-10-22 加载与采集更新

- 首批20家公司不再等待总数、行业聚合和核查队列统计；`listSummary`独立加载。下拉刷新保留上次列表，失败可重试；筛选和翻页用请求序号防止迟到响应混入。
- 首页统计30秒内复用，移除每次打开首页都扫描核实队列的请求；保留抽检警报。
- 采集器每30分钟运行，读取来源最多约30秒，预留数据库写入时间，不同公司最多8路写入；来源失败保留其分页游标，成功来源继续更新。持续失败的分页需通过来源状态排查，不能靠增加触发次数修复。
- `meta/crawler`记录尝试时间、全源成功时间、运行状态与各来源HTTP请求数/耗时；部分失败不会冒充全源更新成功，全源失败不刷新目录时间。首页显示北京时间到分钟的状态。
- `meta/maintain`记录完成时间与部分失败状态；修复抽检读回`_id`后写入触发CloudBase保留字段错误。
- 部署顺序：先增量部署api/index.js与crawler/index.js，更新crawler触发器并核实仅保留every30m，再编译前端。无需更改数据库权限或环境变量。

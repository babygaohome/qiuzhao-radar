# 安全检查范围与发现

日期：2026-09-27。范围：云函数 api/crawler、微信身份边界、私有公司、投递/日程、材料、Offer、AI 方案、面试准备缓存、备份恢复、服务端取网页。优先目标为用户之间的保密性与写入隔离。第三方账户权限、云数据库线上安全规则、微信身份签发、云端加密与基础设施不由本地测试证明。

## 资产和边界

用户身份来自 `cloud.getWXContext().OPENID`，客户端传入的 openid/owner 不作为身份。apps 用 OPENID 前缀，profiles 以 OPENID 为文档 ID，manual companies 绑定 owner；公开公司目录和公开招聘证据为共享数据。preps 原为共享缓存，本轮改为 OPENID + 公司 + 岗位摘要键并保留所有者。AI 密钥在环境变量中，私有材料只由用户主动触发 AI 操作发送至既有服务商。

## 攻击面复审

普通账号通过伪造 openid/owner、传其他人的私有公司 ID、使用相同岗位缓存、恢复带其他人公司 ID 的备份、调用删除接口均在本地测试中被隔离。公开目录内容可由用户反馈触发复核，但反馈自由文字不会出现在其他用户的列表/详情响应。真实云端六集合已核验客户端拒绝直读；未来若改为开放规则，应用层隔离仍可被绕过，因此需保持该配置。没有运行真实用户删除或发送材料至 AI 的测试。

## 2026-09-29 全量复审（取代上面的风险优先级，历史记录保留）

### Scope 与资产

范围：小程序前端、api/crawler/remind 三个云函数、六个数据库集合、外部招聘源与 AI/搜索集成、备份恢复。威胁方：普通已登录小程序用户、恶意招聘信息提供方、被污染的依赖或外部服务。保护目标依次为个人资料保密、共享招聘数据准确、云资源可用。微信身份签发和云平台底层加密不在代码审查能力内。

数据流：小程序使用 `wx.cloud.callFunction` 调用 api；服务端从 `getWXContext().OPENID` 获得身份；apps/profiles/preps/reminders 为个人数据，companies/meta 为共享数据；crawler 定时抓公开站点，api 把部分材料发往智谱 AI 与百度搜索。用户主动导出的 JSON 备份包含投递、材料、Offer 等私人内容。

现网只读核验：六集合均为「所有用户不可读写」；云函数安全规则当前只有 `* → auth != null && auth.loginType != 'ANONYMOUS'`，没有 crawler/remind 的单独拒绝规则；云函数日志服务未开启；api/crawler/remind 均为 Nodejs16.13。真实双微信账号互访没有测试。

### 攻击面与链条

重点链条一：已登录用户直接调用 crawler → 并行重抓、写共享 companies/meta → 函数调用与数据库资源耗尽或数据竞争。重点链条二：来源页给出错误 `post-button` 外链 → crawler 直接标记 official → 用户复制错误的投递入口。高价值目标为个人 profiles/apps、共享 companies 中的核实标志和 AI/搜索额度。未实际进行破坏性或跨账号攻击。

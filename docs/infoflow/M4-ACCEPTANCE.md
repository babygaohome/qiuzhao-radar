# M4 每日简报：部署与验收状态

M4 是站内每日简报，不自动发送微信通知或邮件。资讯来源遵循已配置的受控来源；内容不足时可以为空。

## 已完成

- 本地实现资讯筛选、本人标记岗位的核验、快照、今日和分页历史、已读、资讯收藏与撤销。删除代际与简报开关代际分别隔离，避免旧任务复活或清除新代数据。
- 33 个本地安全与简报测试脚本通过；其中大部分数据库与账号行为使用模拟替身。
- 云端准备了历史列表、启用用户扫描、资讯查询索引；已将 M4 API 部署并开启服务器端简报开关，备份在本任务工作区的 `work/cloud-backup/m4-predeploy`。`intelDigest` 函数使用同一代码、60 秒超时，客户端调用被拒绝。
- 一次性真实 timer 探针观察到可信 `TRIGGER_SRC=timer`、合法事件名和时间；正式函数对手工伪造 timer 调用返回 rejected。
- 两个合成身份在真实 CloudBase 中验证了基本的快照写入、读取、代际变化和一次受控并发交错；当前真实微信身份不能用请求参数冒充合成身份，客户端直接读取偏好/简报集合被拒绝。这些均不等于两个真实微信账号的完整隔离或真实 `deleteAllMine` 验收。
- 正式 `intelDigestHourly` 已启用，每小时检查一次。一次真实定时测试为单独合成偏好生成 2 条来自真实公开来源的资讯，快照读回成功；合成偏好和快照被精确清理并复查零残留。测试后触发器已恢复每小时。`intelCrawlerEvery6Hours` 仍是唯一的资讯采集计划，每 6 小时一次。
- 当前用户在开发者工具独立预览中开启了简报偏好，沿用 `Asia/Shanghai` 和 08:00。正式小程序前端尚未上传体验版或发布；GitHub 中客户端开关仍默认关闭。

## 尚未完成和限制

1. 用户暂时没有两个可清理的微信测试账号，真实双账号、真实删除与导出流程仍未验收；没有使用用户的正式求职数据进行删除测试。
2. 前端预览使用实际云接口，但正式小程序尚未发布，必须经过用户授权的发布流程才对外可见。
3. 北京时间 08:00 对应澳大利亚布里斯班时间 10:00（当前日期）。设置时间后由每小时任务检查，首次用户真实简报是否生成仍需等待实际触发并验证；一次性测试的合成账号结果不能替代此验证。
4. 一次合成并发结果不能覆盖所有 CloudBase 事务交错；若观察到错误，先关闭 worker 和 API 的 `INTEL_DIGEST_ENABLED` 并保留备份和用户数据。
5. 历史岗位会按当前的可见性、核验与时间条件再次过滤，之后可能不再显示；公开资讯标题/来源按当前记录重建，快照的条目 ID 和顺序保持稳定。

脱敏的一次性探针证据保存在本任务的 `outputs/m4-timer-observation.json` 和 `outputs/m4-e2e-observation.json`。临时探针函数、触发器、权限规则及合成记录已清理。

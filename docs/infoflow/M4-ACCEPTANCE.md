# M4 每日简报验收基线（开发中）

M4 目标是站内每日简报；不自动发送微信消息、邮件，也不为每人调用大模型。M3 的真实双账号隔离、删除和导出尚未验证，在这些门槛完成前不得将 M4 部署到现有云环境或宣称全部验收通过。

## 必须验证

- 用户主动启用；按其选择的 IANA 时区和本地时间，处理跨日及夏令时。内容只选时间窗口内可追溯、发布时间明确且已发布的记录；不足配额时展示实际数量。
- 同一用户、本地日期的快照幂等且顺序稳定；其他用户无法读取。更新、重试、部分失败不能误报成功。
- 简报与用户数据删除并发时，旧一代任务不能在删除后重新创建记录；关闭功能同样阻止新快照。用户身份必须来自服务端。
- 现有求职记录只读，继续遵循原有核验、私有隐藏、截止和学历未知等规则；不以简历、Offer 或其他私密材料推断资讯兴趣。
- 前端首屏不等待简报生成；今日和历史页应有加载、空、失败及重试状态。已读和收藏只能作用于本人；不承诺微信通知。
- 针对现有功能运行回归；在有两个可明确识别且可清理的测试账号后，验证隔离、并发删除、导出与删除后重新启用。不得使用真实求职数据进行删除测试。

## 当前进展

此文档是验收基线，不是执行结果。此前 M3 单账号预览已读取真实资讯并验证偏好保存、收藏及撤销；22 个本地安全脚本通过。双账号和真实删除/导出测试尚未进行。M4 尚未部署或发布。

## 本地基础实现（未部署）

已实现受控来源资讯的时间窗口、来源与日期过滤、频道分桶及确定性去重；已实现通过显式接口注入的生成编排和快照存储。快照按用户、日期、删除代际和简报开关代际区分；用户切换简报开关会变更独立代际，不改变收藏与反馈代际。删除旧用户数据时按删除代际清理简报，防止清理新一代数据。上述并发测试使用内存替身，尚不能证明云端事务行为。

本轮本地重新运行既有 22 个安全脚本及 3 个简报专项脚本，均通过。尚未实现或验收：真实云函数包装与安全定时调度、现有求职岗位关联、今日和历史界面、已读/收藏及真实双账号、删除/导出和事务竞态。不得将本轮结果当作 M4 功能已上线。

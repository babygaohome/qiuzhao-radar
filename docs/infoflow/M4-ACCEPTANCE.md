# M4 每日简报验收基线（开发中）

M4 目标是站内每日简报；不自动发送微信消息、邮件，也不为每人调用大模型。M3 的真实双账号隔离、删除和导出尚未验证，在这些门槛完成前不得将 M4 部署到现有云环境或宣称全部验收通过。

## 必须验证

- 用户主动启用；按其选择的 IANA 时区和本地时间，处理跨日及夏令时。内容只选时间窗口内可追溯、发布时间明确且已发布的记录；不足配额时展示实际数量。
- 同一用户、本地日期的快照幂等且顺序稳定；其他用户无法读取。更新、重试、部分失败不能误报成功。
- 简报与用户数据删除并发时，旧一代任务不能在删除后重新创建记录；关闭功能同样阻止新快照。用户身份必须来自服务端。
- 现有求职记录只读，继续遵循原有核验、私有隐藏、截止和学历未知等规则；不以简历、Offer 或其他私密材料推断资讯兴趣。
- 前端首屏不等待简报生成；今日和历史页应有加载、空、失败及重试状态。已读和收藏只能作用于本人；不承诺微信通知。
- 针对现有功能运行回归；在有两个可明确识别且可清理的测试账号后，验证隔离、并发删除、导出与删除后重新启用。不得使用真实求职数据进行删除测试。

## 当前进展

此文档是验收基线，不是执行结果。此前 M3 单账号预览已读取真实资讯并验证偏好保存、收藏及撤销；22 个本地安全脚本通过。双账号和真实删除/导出测试尚未进行。M4 尚未部署或发布。

## 本地基础实现（未部署）

已实现受控来源资讯的时间窗口、来源与日期过滤、频道分桶及确定性去重；已实现通过显式接口注入的生成编排和快照存储。快照按用户、日期、删除代际和简报开关代际区分；用户切换简报开关会变更独立代际，不改变收藏与反馈代际。删除旧用户数据时按删除代际清理简报，防止清理新一代数据。上述并发测试使用内存替身，尚不能证明云端事务行为。

本轮本地重新运行既有安全脚本与简报专项脚本。页面、只读接口和定时入口均为本地实现，尚未接入真实云环境；岗位读取初版尚未接到简报生成。已读/收藏及真实双账号、删除/导出和事务竞态尚未验收。不得将本轮结果当作 M4 功能已上线。

## 部署前索引核对

历史列表按 `openid`、`generation`、`digestGeneration`、`timezone` 筛选并按 `localDate` 倒序；部署前须在目标云环境核实是否需要复合索引，并按实际查询建立、验证。启用用户的分页扫描也须按最终查询确认索引。不得仅凭本地测试认定索引已建立。

## 本地增量（未部署）

新增默认关闭的只读 API、今日/历史页面及分页，新增后台有界调度核心与 CloudBase 存储适配器；页面与接口开关默认关闭。内存联测已覆盖生成到读取、历史、两名模拟用户及错误传播。当前 32 个本地脚本通过；所有真实云事务、索引、定时安全标志和真实账号验收仍未完成。历史列表按快照 ID 重建当前公开资讯，若源文章的标题或来源元数据变化，旧简报的展示文本也会变化；快照的条目 ID 和顺序保持不变。

## 当前本地实现与余项

今日、历史及历史分页页面和只读接口已编写，前后端开关默认关闭。定时函数入口、有限扫描和租约适配器已编写，但未创建线上触发器；入口严格要求平台定时标记，而当前环境此前未提供该标记，故实际运行仍需确认安全调用方式。单用户反复失败时先有限重试，再推进扫描，下一轮重新尝试。

新增岗位读取初版，只读取本人已标记且满足现有核验及可见性规则的记录；明确截止、证据和来源不足则不选，不读取简历、备注或 Offer。该模块还未接入定时生成和界面。历史快照目前固定条目编号与顺序，公开资讯标题和来源后续变化时展示文字会随之变化。

最近一轮 32 个本地安全和简报脚本通过（模拟环境）。上线前仍须补全岗位关联、简报已读与收藏的完整交互、真实双账号及删除/导出和并发验证、云端索引与租约事务验证、定时标记和部署流程；不得据此宣称每日简报已上线。

岗位可见性工厂已与现有 `buildWhere({tab:'all'})` 的实际源码做 10 类本地规则对照；定时函数尚未使用它。要接入岗位还需解决双函数打包、仅投影本人隐藏 ID、候选读取、快照关联与展示，并复测真实隔离。最近一轮合计 33 个本地脚本通过。

## 岗位关联本地增量

定时生成仅在本人主动订阅求职频道时读取本人应用的公司 ID/状态、隐藏公司 ID 和必要的已核验公开岗位字段，使用原可见性规则对照实现；只将最多四个公司 ID 存入快照。读取时重新按当前用户的可见性、核验状态及筛选窗口核验，页面可显示通过核验的岗位。历史岗位在后来过期、被隐藏、取消标记或不再落在当前筛选窗口时可能不再显示；不会保留或展示原始私有资料。该增量仅通过内存模拟联测，真实索引、数据、两个账号和云函数定时入口均未验收；不能视为上线。

# M4 每日简报验收状态

M4 的目标是站内每日简报。微信通知、邮件和为每个用户单独调用大模型均不在当前范围内。所有本地简报开关默认关闭。

## 本地已实现

- 按用户明确设置的时区和本地时间生成资讯窗口，筛选已发布、来源与发布时间可确认的内容；资讯不足时不补造内容。
- 以用户、本地日期、删除代际、简报启用代际及时区隔离快照，并处理同日重复生成、快速关闭再启用和旧请求令牌。
- 今日、历史及分页页面；服务端只读接口；已读和资讯收藏及撤销。
- 求职候选只在用户主动订阅求职频道时读取本人标记的公司 ID 和状态，并套用现有可见性及逐岗核验规则。快照只存有限的公司 ID；读取时再次核验后才展示，不读取简历、备注或 Offer。
- 定时扫描核心包含批次上限、租约适配器和有界失败重试。入口严格要求可信平台定时标记，无法确认触发来源时保持拒绝执行。

上述功能已有专项本地测试和模拟联测。模拟结果不能证明真实微信账号隔离或 CloudBase 事务行为。

## 尚未完成的真实验收

1. M3 的真实双账号隔离、删除与导出仍未验收。用户目前没有两个可用于安全测试的账号；不得用正式求职资料做删除测试。
2. M4 未部署、未创建或启用定时触发器，也未上传体验版或正式发布。现有平台运行环境是否提供 `TRIGGER_SRC=timer` 尚未核实；标志缺失时入口会拒绝扫描。
3. CloudBase 事务在并发删除、已读及重新启用时的真实串行行为尚未验证。
4. 历史查询、偏好扫描及公开资讯查询所需的复合索引尚未在云端核实或创建。
5. 岗位读取的可见性工厂有 10 类与现有 API 规则的本地对照，但真实云数据与索引尚未验收。

部署前应逐项取得隔离账号、触发信任标志、索引和事务测试的真实证据；未通过前保留服务端和客户端开关为关闭。岗位筛选在公司或岗位状态变化后会重新核验，因此历史简报中的岗位可能不再显示；公开资讯标题和来源也会按当前公开记录重建，而快照中的条目 ID 与顺序保持稳定。

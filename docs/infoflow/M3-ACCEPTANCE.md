# M3 部署前与真实环境验收清单

这份清单用于把 M3 从本地测试推进到隔离云环境验收。勾选项必须附当前环境的实际证据；代码测试和历史截图不等于现网验证。M3 的偏好、反馈接口以及现有 `deleteAllMine` / `exportMine` 都会访问新增集合。缺集合时接口会失败，因此不得先发布 API 再补数据库。

## 0. 变更范围与回滚准备

- [ ] 确认目标是隔离的测试环境，记录环境 ID、API 当前版本/部署时间及回滚版本。不要把生产用户用于 A/B 隔离测试。
- [ ] 确认资讯功能服务端开关关闭时旧招聘页面和投递管理仍可用；保存当前可恢复的 API 版本。
- [ ] 先检查当前集合、索引和安全规则，记录已有配置；只添加本阶段所需内容，不覆盖其他规则。
- [ ] 确认开发分支和 PR 基线；按仓库约定保持草稿 PR，不合并到主分支、不发布小程序。

## 1. 建立集合与客户端权限

在目标云环境预建以下三个集合。每一个集合都要单独确认客户端读、写、更新、删除均被拒绝；API 云函数服务身份仍需有必要的数据读写权限。不要假设“仅前端不显示”就是权限保护。

| 集合 | 用途 | 需要验证的服务端访问 | 客户端规则 |
| --- | --- | --- | --- |
| `intel_preferences` | 以服务端微信身份对应的 `_id` 保存偏好、revision、generation 和删除标记 | 按 `_id` 读取；按 `_id` 与 revision 条件更新；首次写入及删除标记新增 | 拒绝所有客户端读写 |
| `intel_feedback` | 保存明确的喜欢、收藏、不感兴趣状态 | 按哈希 `_id` 读写；按服务端 `openid` 查询；删除时按 `openid` 与 generation 清理 | 拒绝所有客户端读写 |
| `intel_digests` | 预留简报快照；M3 不生成简报 | 删除时按服务端 `openid` 清理；导出时按 `openid` 查询 | 拒绝所有客户端读写 |

- [ ] 从客户端直接尝试读、写、更新、删除每个集合，逐项确认拒绝；只记录操作结果，不保存用户凭据或完整响应里的身份标识。
- [ ] 从云函数服务端执行 M3 接口的最小读写，确认云函数权限可用。
- [ ] 如需手动创建索引，先以目标环境实际查询和数据库提示为准。建议检查 `intel_feedback(openid)` 与 `intel_feedback(openid, generation)`、`intel_digests(openid)`；偏好通过 `_id` 主键访问。资讯读取使用 `intel_items(status, _id)` 的过滤加排序。设计文档中的推荐索引可供核对，不代表这些索引已创建或被当前查询使用。
- [ ] 保存集合权限与索引页面的脱敏证据；截图及日志不得包含 OPENID、游标密钥、认证令牌或用户内容。

## 2. 部署前检查

- [ ] 检查目标环境已具备 M1/M2 所需集合，并确认 crawler 仍由服务端触发、客户端不能直接调用；保持既定六小时调度。
- [ ] 在隔离环境部署 API 之前再次确认上述三个 M3 集合存在且客户端规则为拒绝。部署完成后优先调用只读偏好接口，再按顺序验证写入和删除。
- [ ] 服务端分页密钥 `INFOFLOW_CURSOR_SECRET` 必须在云函数环境变量中设置，至少 32 字符；只确认“已配置/未配置”，不复制到聊天、命令行记录、截图、PR 或日志。
- [ ] 确认 `INTEL_ENABLED`（或当前代码对应的开关）初始关闭；按代码当前实际变量名核对，不能凭文档推断变量名。
- [ ] 确认日志只记录动作、结果码和必要耗时；不输出明文 OPENID、简历/JD、游标密钥、完整分页游标或文章正文。

## 3. 两个测试账号的隔离验收

使用两个独立、可控的微信测试账号 A 和 B。记录步骤、预期与通过/失败，不在验收文档中记录其 OPENID。

1. A、B 分别读取默认偏好，确认初始值互不影响。
2. A 修改频道偏好并增加一条反馈；B 读取自己的设置和同一资讯，确认看不到 A 的偏好或反馈。
3. B 尝试通过接口参数指定 A 的用户标识读取/修改数据；确认服务端仍只按登录身份处理，不接受请求体的身份替换。
4. A、B 各自更新 revision；重复提交旧 revision 应返回冲突，并让客户端刷新后再保存。
5. 用 A 的分页游标在 B 的会话继续请求，确认请求失败；修改偏好或反馈后继续用 A 的旧游标，应提示刷新。不得在报告中粘贴游标。
6. 尝试开启隐式行为学习，确认被拒绝或保持关闭；确认不会从简历、投递资料或浏览行为推断偏好。

## 4. 删除、导出与并发

- [ ] 先让 A 保存偏好和反馈；导出 A 的数据，确认导出字段范围明确且只包含 A 的记录。导出样本应脱敏并及时删除。
- [ ] 执行 A 的“删除本人数据”，确认偏好被清除/标记、反馈和简报记录清理，原有求职数据的删除行为仍符合既有产品定义。
- [ ] 删除后重新读取 A 的数据，确认不会返回旧反馈或旧偏好；B 的记录保持不变。
- [ ] 在隔离测试中让删除与偏好保存/反馈写入并发，确认删除后的旧 generation 写入不能复活；发生冲突时返回可理解错误。
- [ ] 对集合暂时不可用或服务端访问失败做受控验证，确认删除/导出失败明确返回错误，不会误报成功或空导出。
- [ ] 删除后重新启用偏好，再写入新反馈；确认旧 generation 反馈不会混入新状态。

## 5. 前端与旧功能验收

- [ ] 在微信开发者工具中用 A、B 分别打开真实隔离环境，检查偏好读取/保存、反馈/撤销、分页刷新和错误提示。
- [ ] 检查弱网/接口超时和快速切换分类时，旧请求结果不会覆盖当前分类。
- [ ] 检查暗色模式、列表滚动、详情返回和小屏布局。
- [ ] 用旧客户端或回归用例确认原招聘列表、岗位详情、收藏/投递管理及提醒仍可使用。
- [ ] 明确验证边界：M3 当前没有实现每日简报生成或微信通知；`intel_digests` 仅为删除/导出兼容预建。

## 6. 回滚与收尾

- [ ] 若 M3 接口影响旧功能，先关闭服务端资讯开关并停止新入口流量；保留集合和数据，回滚 API 到已记录版本。不要直接删集合。
- [ ] 调查并修正权限、索引或代码问题后，在隔离环境重跑失败步骤，再考虑下一阶段。
- [ ] 验收完成后确认 crawler 仍只有已批准的六小时触发器，没有遗留分钟级计划；M3 不应修改采集计划。
- [ ] 汇总环境、版本、每项结果、证据位置及未通过项。标注“本地测试”“隔离云环境”“微信开发者工具”各自的结果，不能把其中一种写成生产验收。

## 当前状态

本文件是操作清单，不是执行记录。当前 M3 的本地测试结果见 [M3.md](M3.md)；三个集合已在现有云环境创建并读回 ADMINONLY；开发者工具已验证真实资讯、偏好读取与保存、收藏及撤销。双账号隔离和真实删除/导出仍未验证；完整验收须保留脱敏证据。

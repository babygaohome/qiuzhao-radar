# M3 兴趣与反馈开发记录

提供本人频道偏好、细分兴趣及语言/时间设置；明确订阅的频道优先，同组按原时间排序。喜欢、收藏、不感兴趣支持撤销；细分兴趣、语言和反馈暂不参与排序。隐式行为学习不能开启，未从简历或其他个人材料推断兴趣。简报生成及微信通知尚未实现。

权限依据服务端身份。偏好保存采用版本检查，反馈和偏好按用户限流；删除与重新启用使用代际隔离，删除和导出错误不会被当成成功。排序或反馈改变后旧分页提示刷新。

本地全量23个测试脚本通过，包含账号隔离、首次写入竞争、删除与重新启用竞态、失败注入和分页冲突。mock 不能证明现网权限或真实双账号隔离。

部署前必须预建 intel_preferences、intel_feedback、intel_digests 并逐一设置客户端不可读写，确认索引与云函数权限，再在隔离环境做真实双账号、删除/导出及开发者工具渲染验证。当前接口及旧版删除/导出依赖这些集合，缺失集合时会报错；不可先部署 API。未操作线上资源。

## 2026-10-29 现有云环境试验

用户批准在现有环境验收。新建 `intel_preferences`、`intel_feedback`、`intel_digests`，逐项读回 `ADMINONLY`；新增 feedback 的 `(openid, generation)` 和 digests 的 `openid` 索引。上传 M3 API 后开发者工具偏好读取返回服务错误，原因尚未确认；已回滚 API 并下载核对入口文件与部署前备份哈希一致。真实资讯在第一次回滚后恢复显示。保留新增集合，不删除用户数据。未执行真实账号删除、导出或双账号隔离测试；未发布小程序。

本地增加对 CloudBase 缺失文档错误码 `-502005` 的处理与测试，这是待真实验证的可能修复，不是根因已确认。复测通过 `intel-user-data.test.cjs`、`infoflow.test.cjs`、`intel-preferences-pages.test.cjs`。采集器在部署期间读回仍为一个已启用的六小时定时器；尚未证明新的自然定时执行结果。

后续验证：把上述缺失文档兼容修复部署后，待函数 Active 再读取兴趣设置，页面仍返回服务错误；该修复未解决实际故障，已再次回滚 API。真正错误原因仍未知，不应重复宣称修复成功。

更正：`-502005` 也被腾讯文档标为数据库权限错误，不能当作记录不存在而吞掉；上述未解决问题的临时本地修正已撤回，错误继续透传。另建立只访问虚构记录、只返回错误分类的独立诊断函数 `intelM3Diagnostic`；首次运行缺少依赖，重新部署依赖时平台持续显示 Updating，诊断尚无结果。主 API 保持回滚版本。

## 真实读取修复和验收进展（覆盖前述临时状态）

独立诊断使用虚构 ID 证实 SDK 4.0.2 对不存在文档返回 `document.get:fail document with _id ... does not exist`、errCode=-1。M3 现在识别该明确错误，权限、集合及其他错误继续抛出；未使用 -502005 判定缺失。部署更新后函数 Active，开发者工具中的真实资讯、偏好默认值读取和保存、收藏与撤销均已实际通过；使用当前开发者账号保存默认偏好，测试收藏已撤销。独立诊断函数已删除。新增集合仍为 ADMINONLY，采集器仅有一个启用的六小时触发器。双账号隔离以及真实账号删除/导出仍未验证；前端为开发者工具独立预览，未上传体验版或正式发布。
